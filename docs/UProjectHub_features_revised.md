# UProject Hub — 추가 기능 후보 정리본

이 문서는 UProject Hub에 추가하거나 기존 기능에 통합할 기능 후보를 정리한 문서다.

기능에 따라 기존 UI와 동작을 보완할 수도 있고, 새로운 기능으로 추가할 수도 있다. 구체적인 구현 범위와 순서는 각 기능을 개발할 때 별도로 결정한다.

---

## 1. 프로젝트별 Quick Actions

프로젝트를 우클릭했을 때 표시되는 메뉴의 주요 동작과 명칭을 다음과 같이 정리한다.

- **Unreal에서 열기**
- **기존 `.sln` 열기**
- **프로젝트 폴더 열기**
- **Generate Visual Studio Project Files**
- **Switch Unreal Engine Version**

기존의 `.uproject 위치 열기` 항목은 삭제한다.

### 기존 `.sln` 열기

C++ 프로젝트이고 기존 `.sln` 파일이 있을 때 해당 솔루션을 연다. Blueprint 프로젝트이거나 `.sln` 파일이 없으면 사용할 수 없다는 점이 명확하게 표시되어야 한다.

### Generate Visual Studio Project Files

C++ 프로젝트의 Visual Studio 프로젝트 파일을 다시 생성한다. `.sln` 파일이 없거나 `Intermediate/ProjectFiles`를 다시 만들어야 할 때 사용할 수 있다.

실행 전에는 다음 정보를 확인할 수 있어야 한다.

- 사용할 Unreal Engine
- 대상 `.uproject` 경로
- 실행할 작업

작업 중에는 UI를 멈추지 않아야 하며, 완료 또는 실패 결과를 사용자에게 알려야 한다.

### Switch Unreal Engine Version

설치 또는 등록된 Unreal Engine 중 하나를 선택해 프로젝트의 연결 엔진을 변경한다.

엔진 버전 변경은 프로젝트 호환성에 영향을 줄 수 있으므로 다음 내용을 명확하게 안내한다.

- 현재 연결된 엔진
- 변경할 엔진
- 다른 버전에서 열면 프로젝트 데이터가 변환될 수 있다는 경고
- 변경 후 이전 엔진에서 다시 열리지 않을 수 있다는 경고

사용자가 대상 엔진과 경고 내용을 확인한 뒤 명시적으로 실행해야 한다. 엔진을 자동으로 선택하거나 사용자 확인 없이 변경해서는 안 된다.

## 2. 프로젝트 상태 진단

프로젝트 목록에 `UE 5.8 / C++` 같은 기본 정보만 표시하는 것을 넘어, 프로젝트를 열기 전에 확인할 수 있는 상태 정보를 제공한다.

표시 예시:

**Healthy**

> UE 5.8.2 · C++ · Ready

**Warning**

> ⚠ Engine 5.7 not installed

**Warning**

> ⚠ `.sln` missing

**Error**

> ✕ Project folder missing

**Warning**

> ⚠ Plugin dependency missing

확인할 수 있는 항목:

- 연결된 Unreal Engine 설치 여부
- `.uproject` 파싱 가능 여부
- C++ 프로젝트인데 `.sln`이 없는지
- `Source/` 존재 여부
- 엔진 경로가 유효한지
- 프로젝트 경로가 유효한지
- 프로젝트가 다른 Unreal Engine 버전을 요구하는지
- 필요한 플러그인이 누락되었는지
- 프로젝트가 있는 드라이브의 여유 공간이 부족한지
- 마지막 실행 실패 흔적이 있는지

목록에는 가장 중요한 상태를 간결하게 표시하고, 프로젝트를 선택하거나 상태를 클릭하면 자세한 진단 내용을 확인할 수 있게 한다.

정상 상태는 조용하게 표시하고, 사용자의 조치가 필요한 경고와 오류가 더 잘 구분되도록 한다. 한 프로젝트의 진단 실패가 다른 프로젝트의 조회나 실행을 방해해서는 안 된다.

## 3. 프로젝트 용량 분석 및 프로젝트 캐시 정리

프로젝트의 전체 용량과 주요 폴더별 용량을 확인할 수 있게 한다.

표시 예시:

> **전체 용량: 37.4 GB**

| 폴더 | 용량 |
|---|---:|
| Content | 14.8 GB |
| DerivedDataCache | 10.2 GB |
| Intermediate | 6.1 GB |
| Saved | 3.8 GB |
| Binaries | 2.1 GB |
| Source | 91 MB |

용량 계산은 프로젝트를 선택하고 사용자가 요청했을 때 실행한다. 목록을 불러올 때 모든 프로젝트의 폴더를 자동으로 순회해서는 안 된다.

분석 중에는 진행 상태와 취소 기능을 제공하고, 일부 파일이나 폴더에 접근할 수 없더라도 가능한 범위의 결과를 계속 표시한다. 마지막 분석 결과와 계산 시각을 저장해 같은 내용을 불필요하게 반복 계산하지 않도록 한다.

### 프로젝트 캐시 정리

프로젝트 내부의 다음 캐시 또는 생성 폴더를 선택하여 삭제할 수 있게 한다.

- `Intermediate/`
- `DerivedDataCache/`
- `.vs/`

정리를 실행하기 전에 각 폴더의 정확한 경로와 삭제 대상 파일의 논리적 크기 합계를 보여주고, 사용자가 삭제할 폴더를 개별적으로 선택할 수 있게 한다. 이 값은 실제 물리 디스크 확보량을 의미하지 않는다. 최종 확인 없이는 삭제하지 않는다.

다음 항목은 프로젝트 캐시 정리 대상에 포함하지 않는다.

- `.uproject`
- `Content/`
- `Config/`
- `Source/`
- `Plugins/`
- `Saved/`
- `Binaries/`

삭제 대상은 반드시 선택한 프로젝트 디렉터리 내부의 정확한 폴더로 제한한다. Unreal Editor, Visual Studio 또는 관련 빌드 프로세스가 프로젝트를 사용 중이면 먼저 종료하도록 안내한다.

정리가 끝나면 폴더별 성공 또는 실패 결과와 삭제된 파일의 논리적 크기 합계를 표시한다. 정리 후에는 프로젝트 파일 재생성, 셰이더 재컴파일 또는 캐시 재생성 때문에 다음 실행 시간이 길어질 수 있음을 미리 알린다.

## 4. 프로젝트 태그

프로젝트에 사용자가 자유롭게 태그를 지정할 수 있게 한다.

예시:

> ue260826_SMB  
> `Study` `Paper2D` `C++`

> TeamProject  
> `School` `Team` `Portfolio`

태그를 검색 조건으로 사용할 수 있게 한다.

```text
tag:portfolio
tag:study engine:5.8
```

태그는 프로젝트 파일이 아니라 UProject Hub의 사용자 설정에 저장한다. 프로젝트 목록에서는 정보 밀도를 해치지 않는 범위에서 일부 태그를 표시하고, 프로젝트 상세 정보에서는 전체 태그를 확인하고 편집할 수 있게 한다.

## 5. 프로젝트 메모

프로젝트별로 간단한 메모를 작성할 수 있게 한다.

예시:

> Paper2D 마리오 테스트  
> 카메라 구현까지 완료  
> 다음: 굼바 AI

여러 공부용 프로젝트나 실험 프로젝트를 관리할 때 현재 진행 상황과 다음 작업을 기록하는 용도로 사용한다.

메모를 검색 조건으로 사용할 수 있게 한다.

```text
note:camera
```

메모는 프로젝트 파일을 변경하지 않고 UProject Hub의 사용자 설정에 저장한다. 프로젝트가 일시적으로 누락된 상태에서도 메모가 바로 사라지지 않아야 한다.

## 6. 간단한 Git 상태 표시

프로젝트가 Git 저장소에 연결되어 있는지와 마지막 커밋 이후 변경 사항이 있는지를 간단하게 표시한다.

표시 상태 예시:

- **Git 연결 안 됨**
- **Git 연결됨 · 커밋 이후 변경 없음**
- **Git 연결됨 · 커밋 이후 변경 있음**
- **Git 상태 확인 실패**

Git 상태는 프로젝트를 선택했을 때 또는 사용자가 새로고침을 요청했을 때 확인한다. 프로젝트 목록 전체를 불러올 때 모든 프로젝트의 Git 상태를 자동으로 검사해서는 안 된다.

Git에 연결된 프로젝트의 상태 영역을 클릭하면 해당 저장소의 GitHub 웹사이트를 기본 브라우저에서 연다. GitHub 원격 저장소 주소를 확인할 수 없으면 링크를 비활성화하고 그 이유를 알려준다.

UProject Hub 안에서 커밋, Push, Pull, 브랜치 변경 같은 Git 클라이언트 기능은 제공하지 않는다.
